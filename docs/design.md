# DQL provider

A Terraform provider whose functions compile DQL queries at plan time. It embeds the `dql-compiler` library; the language, its grammar versions and every backend's rules are that library's design. A configuration states a query once and Terraform renders it into the native query each consumer takes.

The provider has no configuration, resources or data sources. Functions need Terraform 1.8 or later.

## Functions

| Function | Signature | Returns |
|---|---|---|
| `provider::dql::promql` | `(query string, grammar_version string...)` | the PromQL expression |
| `provider::dql::opensearch` | `(query string, config object({ time_field = string, group_limit = number }), grammar_version string...)` | the OpenSearch search request body, a JSON string for `jsondecode` |

- `grammar_version` is the grammar version the query is written in. Omitted, it is the latest the bundled compiler supports: each provider release is built with one compiler version, so the provider pin decides it.
- A query the compiler refuses fails the plan with the compiler's message, on the argument that is wrong: an unsupported version on `grammar_version`, anything else on `query`.
- `opensearch`'s `config` is the OpenSearch backend's configuration: the field a time function buckets by, and how many groups each grouping field answers.

## Releases

A release is a version tag with the archives the Terraform Registry reads: one zip per platform, a SHA-256 checksums file signed with the provider's GPG key, and the registry manifest declaring protocol 6.

A snapshot is a pre-release of the same shape, tagged `v<next patch>-snapshot.<UTC timestamp>` from `main` when the snapshot workflow is dispatched. The Registry serves it like a release, and Terraform installs it only when a configuration pins that exact version.

The Registry pages are `docs/`, generated by `make docs` from the functions' definitions and `examples/`.
